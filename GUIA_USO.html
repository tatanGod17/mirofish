1. ¿Qué es MiroFish?

MiroFish es un motor de simulación de opinión social basado en IA. Toma documentos reales (PDFs, textos) sobre cualquier tema, construye un grafo de conocimiento, simula cómo distintos perfiles de personas reaccionarían ante ese tema en redes sociales (Twitter/Reddit), y genera un reporte predictivo completo.

¿Para qué sirve?

  • Investigación de mercado: predecir cómo reaccionará el público ante el lanzamiento de un producto.
  • Análisis de riesgo: detectar posibles controversias antes de publicar una iniciativa.
  • Estrategia de comunicación: entender qué métricas y argumentos resuenan más.
  • Proyectos académicos: simular dinámica de opiniones sobre temas sociales, políticos o empresariales.
  • Business Intelligence: obtener retroalimentación simulada de usuarios antes de implementar una solución.

3. Cómo correr el proyecto

Primer arranque (instalación completa)

Abre dos terminales apuntando a la carpeta del proyecto.

Terminal 1 — Backend

# Ir a la carpeta del backend
cd /ruta/al/proyecto/MiroFish/backend

# Instalar dependencias (solo la primera vez)
~/.local/bin/uv sync --python 3.12

# Iniciar el servidor
~/.local/bin/uv run python run.py

Terminal 2 — Frontend

# Ir a la carpeta del frontend
cd /ruta/al/proyecto/MiroFish/frontend

# Instalar dependencias (solo la primera vez)
npm install

# Iniciar el servidor de desarrollo
npm run dev

Abre tu navegador en http://localhost:3000

Arranques posteriores (ya instalado)

# Terminal 1 — Backend
cd MiroFish/backend && ~/.local/bin/uv run python run.py

# Terminal 2 — Frontend (si no está corriendo)
cd MiroFish/frontend && npm run dev
Nota: El frontend (Vite) raramente necesita reiniciarse. Solo reinícialo si haces cambios en la configuración o hay un error de compilación. El backend sí requiere reinicio cuando cambias el archivo .env.

4. Los 5 pasos del flujo de trabajo

El flujo es lineal: cada paso depende del anterior. Usa la barra de progreso en la parte superior de la app.

1
Upload & Ontology Generation GPT-4o-mini

¿Qué hace?

Sube uno o más documentos (PDF, TXT, MD) y describe el objetivo de la simulación. El sistema extrae el texto, lo analiza con GPT-4o-mini y genera una ontología: el mapa conceptual de entidades y relaciones relevantes para el tema.

Qué ingresas

  • Archivo(s) con información del tema (informes, artículos, documentos de negocio)
  • Descripción del objetivo: "Quiero predecir la reacción del público ante el lanzamiento de esta app"

Qué retorna

  • Lista de tipos de entidades (Ej: Usuario, Empresa, Producto)
  • Lista de tipos de relaciones (Ej: USA, TRABAJA_EN, OPINA_SOBRE)
  • Resumen del análisis del documento

Duración aproximada

30–90 segundos (depende del tamaño del documento).

Puedes editar manualmente la ontología generada antes de continuar al paso 2.
2
Build Knowledge Graph Zep Cloud

¿Qué hace?

Toma el texto del documento, lo divide en fragmentos (chunks) y los sube a Zep Cloud como "episodios de memoria". Zep procesa el texto, identifica entidades y relaciones según la ontología, y construye un grafo de conocimiento estructurado.

Qué retorna

  • Grafo visual con nodos (entidades) y aristas (relaciones)
  • Número de nodos y aristas creados
  • El grafo queda guardado en Zep Cloud para los pasos siguientes

Duración aproximada

2–10 minutos (Zep necesita tiempo para procesar los episodios en su infraestructura).

Este paso consume tu cuota de episodios Zep. El plan gratuito tiene 1,000 episodios/mes. Un documento típico usa 30–80 episodios. Si falla con error 403, ver sección 6.
3
Generate Simulation Config GPT-4o-mini Zep

¿Qué hace?

Lee el grafo de conocimiento y genera la configuración para la simulación OASIS. Esto incluye crear perfiles de agentes simulados (personas ficticias con biografías, profesiones, opiniones) que representan diferentes segmentos de la población.

Qué retorna

  • Archivos de configuración para Twitter simulado y Reddit simulado
  • Perfiles de 20–100 agentes (personas ficticias con nombre, edad, profesión, bio, opiniones)
  • Tópico inicial de discusión

Duración aproximada

3–8 minutos.

Si este paso se queda "generando" por más de 15 minutos sin avanzar, revisa los logs del backend. Puede ser un problema de rate limit con Zep.
4
Run Simulation OASIS GPT-4o-mini

¿Qué hace?

Inicia el motor OASIS (Open Agent Social Interaction Simulation). Cada agente creado en el paso 3 empieza a publicar, comentar y reaccionar como si fuera una red social real. El sistema simula N rondas de interacción.

Qué retorna

  • Feed de publicaciones simuladas (estilo Twitter/Reddit)
  • Estadísticas de interacción (likes, comentarios, shares)
  • Estado emocional y evolución de opinión de cada agente
  • Los resultados se guardan en el grafo Zep como nueva memoria

Duración aproximada

5–20 minutos (depende del número de rondas configuradas).

Consume tokens de OpenAI. Cada agente por cada ronda hace una llamada LLM. 50 agentes × 10 rondas = ~500 llamadas LLM.
5
Generate Report GPT-4o-mini Zep

¿Qué hace?

Un agente de IA lee el grafo de conocimiento + los resultados de la simulación y produce un reporte analítico estructurado en múltiples secciones. Usa herramientas de búsqueda semántica sobre el grafo para extraer insights.

Qué retorna

  • Reporte en formato Markdown con 4 secciones temáticas
  • Métricas clave, análisis de sentimiento, recomendaciones
  • Botón de descarga del reporte (.md) al finalizar
  • El archivo se guarda en backend/uploads/reports/

Duración aproximada

10–40 minutos (el agente hace múltiples búsquedas en Zep).

Al terminar aparece el botón "Download Report (.md)". Puedes abrir ese archivo en VS Code, Notion, Obsidian o cualquier lector Markdown para leer y compartir el reporte.

5. Gestión del backend

¿Cuándo reiniciar el backend?

Situación¿Reiniciar?
Cambiaste una clave en el archivo .env✅ Sí, siempre
Modificaste un archivo .py del backend✅ Sí (Flask lo hace automáticamente en modo debug)
El proceso crasheó o no responde✅ Sí
Cambiaste archivos del frontend (.vue, .js)❌ No (Vite recarga solo)
Cambiaste archivos de traducción (locales/*.json)❌ No (Vite recarga solo)
Importante: Si el backend se reinicia mientras hay un reporte o simulación en progreso, esa tarea se cancela. Tendrás que volver a iniciarla desde la app.

Cómo reiniciar el backend

Opción A — Terminar el proceso actual y volver a correrlo

# En una terminal nueva, matar el proceso en el puerto 5001
lsof -ti:5001 | xargs kill -9

# Reiniciar
cd MiroFish/backend
~/.local/bin/uv run python run.py

Opción B — En la terminal donde está corriendo

# Presiona Ctrl+C para detenerlo, luego:
~/.local/bin/uv run python run.py

Verificar que el backend está corriendo

curl http://localhost:5001/health
# Respuesta esperada: {"service": "MiroFish Backend", "status": "ok"}

O simplemente abre http://localhost:5001/health en tu navegador.

6. Gestión de claves API

¿Dónde están las claves?

Todas las claves están en el archivo MiroFish/.env en la raíz del proyecto.

# Clave OpenAI — para todas las llamadas LLM
LLM_API_KEY=sk-proj-XXXXXXXXXXXXXXXX
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_NAME=gpt-4o-mini

# Clave Zep Cloud — para el grafo de memoria
ZEP_API_KEY=z_1dWlk...XXXXXXXXXXXXXXXX

Cómo actualizar una clave

  1. Abre el archivo .env con cualquier editor de texto
  2. Reemplaza el valor de la clave (solo el valor, no el nombre)
  3. Guarda el archivo
  4. Reinicia el backend (ver sección 5)

Cómo probar si las claves funcionan

Probar clave OpenAI

cd MiroFish/backend
~/.local/bin/uv run python -c "
from app.utils.llm_client import LLMClient
client = LLMClient()
result = client.chat([{'role': 'user', 'content': 'Say hi'}], max_tokens=5)
print('OK:', result)
"
# Si sale "OK: Hi" → la clave funciona
# Si sale "AuthenticationError" → la clave es inválida

Probar clave Zep

~/.local/bin/uv run python -c "
import uuid, os
from dotenv import load_dotenv; load_dotenv('../.env')
from zep_cloud.client import Zep
client = Zep(api_key=os.getenv('ZEP_API_KEY'))
g = client.graph.create(graph_id=str(uuid.uuid4()), name='test')
print('OK - Zep funciona, cuota disponible')
"
# "OK" → funciona y hay cuota
# "401 unauthorized" → clave inválida
# "403 episode usage limit" → cuota agotada

Dónde obtener nuevas claves

ClaveURLPasos

¿Qué hacer cuando se agota la cuota Zep?

  1. Opción A — Esperar el reset mensual (gratis, automático)
  2. Opción B — Borrar grafos viejos: ve a app.getzep.com → tu proyecto → elimina grafos de simulaciones anteriores
  3. Opción C — Nueva cuenta con otro email: registra tuemail+2@gmail.com en app.getzep.com (funciona como email diferente)
  4. Opción D — Upgrade a plan pagado: app.getzep.com/billing

7. Errores comunes y soluciones

ErrorCausaSolución
401 unauthorized (Zep) La API key de Zep es inválida o fue regenerada Genera nueva key en app.getzep.com y actualiza el .env
403 episode usage limit (Zep) Agotaste los 1,000 episodios del plan gratis Borra grafos viejos, espera el reset mensual, o crea nueva cuenta
429 rate limit (Zep) Más de 5 llamadas/minuto al API de Zep El sistema reintenta automáticamente. Solo espera.
401 AuthenticationError (OpenAI) La API key de OpenAI es inválida o expiró Genera nueva key en platform.openai.com/api-keys
429 RateLimitError (OpenAI) Excediste tokens por minuto (200k TPM en plan free) El sistema reintenta automáticamente con backoff exponencial
500 Internal Server Error Error genérico del backend Revisa los logs del backend en la terminal para ver el error exacto
Frontend no carga El servidor de Vite no está corriendo Corre npm run dev en la carpeta frontend/
Paso se queda "generando" para siempre El backend crasheó o hay un error silencioso Revisa los logs del backend; reinicia si es necesario
"Interview failed" en el reporte La simulación OASIS no está activa en ese momento Normal — el reporte continúa con otras herramientas
Reporte en idioma incorrecto El idioma por defecto era chino en versiones antiguas El idioma por defecto ya es inglés. Inicia un nuevo reporte.
