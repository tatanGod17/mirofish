1. Visión General del Proyecto

MinkOracle (anteriormente MiroFish) es un motor de simulación de inteligencia de enjambre que permite predecir el comportamiento colectivo de agentes en redes sociales. A partir de un único documento (PDF, Markdown o texto), el sistema construye automáticamente un grafo de conocimiento, genera perfiles de agentes realistas y simula su interacción en plataformas como Twitter y Reddit.

Propuesta de valor: Sube un documento de contexto → MinkOracle genera hasta millones de agentes IA → simula sus decisiones en redes sociales → produce reportes predictivos accionables.

¿Qué puede hacer MinkOracle?

  • Análisis de documentos: Extrae automáticamente entidades, relaciones y ontología de cualquier documento corporativo o de investigación.
  • Construcción de grafos: Crea un Knowledge Graph enriquecido en Zep Cloud con todas las entidades y sus relaciones.
  • Generación de agentes: Convierte entidades del grafo en perfiles de agentes IA con personalidades, historiales y comportamientos únicos.
  • Simulación de redes sociales: Ejecuta la simulación en plataformas Twitter/Reddit con el framework OASIS/CAMEL-AI.
  • Reportes inteligentes: El ReportAgent utiliza razonamiento ReACT para generar análisis profundos con insights accionables.
  • Chat interactivo: Interactúa con el ReportAgent para hacer preguntas de seguimiento sobre los resultados.

Casos de Uso Principales

📊 Análisis de Opinión Pública

Predice cómo reaccionará el público ante lanzamientos de productos, campañas o eventos usando agentes que simulan comportamiento real.

🔬 Investigación Social

Estudia dinámicas grupales complejas: propagación de información, formación de opiniones, detección de cámaras de eco.

🎯 Marketing Predictivo

Optimiza estrategias de comunicación antes de ejecutarlas, encontrando el "óptimo local" entre diferentes enfoques.

⚡ Análisis de Crisis

Simula escenarios de crisis para anticipar reacciones y preparar respuestas estratégicas con antelación.

3. Servicios de IA & LLM Utilizados

ℹ️
MinkOracle usa el formato OpenAI SDK como interfaz unificada. Esto permite conectar cualquier proveedor compatible (Alibaba Qwen, OpenAI GPT, Deepseek, Mistral, etc.) simplemente cambiando las variables de entorno.

Proveedor LLM Principal — Alibaba Qwen (Recomendado)

🤖 Alibaba Cloud Bailian — Modelo: qwen-plus

Proveedor recomendado por costo-eficiencia. Soporta el formato OpenAI SDK directamente.

  • URL base: https://dashscope.aliyuncs.com/compatible-mode/v1
  • Modelos recomendados: qwen-plus, qwen-turbo, qwen-max
  • Consola: https://bailian.console.aliyun.com/
  • Nota: Las simulaciones consumen bastante — comenzar con menos de 40 rondas.

Proveedor LLM Alternativo — OpenAI

🔷 OpenAI — Modelos GPT-4o / GPT-4o-mini

Compatible directamente. Solo cambiar la API Key y dejar la URL vacía (usa el default de OpenAI).

  • URL base: https://api.openai.com/v1 (default del SDK)
  • Modelos: gpt-4o, gpt-4o-mini, o1-mini

Zep Cloud — Knowledge Graph & Memoria

🕸️ Zep Cloud — Motor de Grafo de Conocimiento

Servicio central para almacenar, enriquecer y consultar el grafo de entidades. El tier gratuito mensual soporta casos de uso simples.

  • Función en Step 2: Construye el Knowledge Graph con ontología definida en Step 1
  • Función en Step 3: Lee entidades filtradas para generar perfiles de agentes
  • Función en Step 5: ReportAgent usa Zep para búsqueda híbrida (InsightForge, PanoramaSearch)
  • Registro: https://app.getzep.com/

OASIS + CAMEL-AI — Motor de Simulación

⚡ OASIS (camel-oasis 0.2.5) + CAMEL-AI (camel-ai 0.2.78)

Framework de código abierto para simulación multi-agente en redes sociales. Cada agente simula comportamiento en Twitter y/o Reddit.

  • Plataformas simuladas: Twitter (tweets, likes, retweets, follows) y Reddit (posts, comments, upvotes)
  • Escalabilidad: Soporta desde decenas hasta millones de agentes (depende de recursos)
  • No requiere API keys: Simulación completamente local

Herramientas del ReportAgent (Zep Tools)

Herramienta Función Cuándo se usa
InsightForge Búsqueda híbrida profunda con sub-preguntas generadas por LLM y recuperación multi-dimensional Análisis principal de cada sección del reporte
PanoramaSearch Búsqueda amplia incluyendo datos expirados en el grafo de Zep Contexto histórico y datos de largo plazo
Interview Conversación directa con agentes individuales del grafo Perspectivas individuales de agentes específicos

5. Pipeline de 5 Pasos – Detalle Técnico

✅
El pipeline es secuencial: cada paso produce outputs que son inputs del siguiente. El estado se persiste en disco, permitiendo retomar desde cualquier punto.
1
Generación de Ontología & Construcción del Grafo OntologyGenerator + GraphBuilderService

¿Qué hace? El usuario sube uno o más documentos (PDF/MD/TXT) junto con una descripción del objetivo de la simulación. El sistema extrae el texto, lo analiza con LLM y genera una ontología estructurada con tipos de entidades y relaciones. Luego construye el Knowledge Graph en Zep Cloud.

POST /api/graph/ontology/generate → Genera ontología (10 tipos de entidad, 6-10 tipos de relación) POST /api/graph/build → Construye el Knowledge Graph en Zep con la ontología
PyMuPDF LLM (JSON mode) Zep Cloud Graph Chunking configurable

Outputs: project.json con texto extraído, ontología definida y graph_id de Zep.

2
Preparación del Entorno de Simulación ZepEntityReader + OasisProfileGenerator + SimulationConfigGenerator

¿Qué hace? Lee las entidades del Knowledge Graph de Zep y convierte cada una en un perfil de agente OASIS con personalidad, historia y comportamientos detallados. Simultáneamente genera la configuración completa de la simulación usando LLM.

POST /api/simulation/prepare → Lee entidades de Zep + genera perfiles de agentes
Zep Entity Reader OASIS Profiles LLM (persona generation) 5 workers paralelos

Outputs: reddit_profiles.json, twitter_profiles.csv, simulation_config.json

3
Ejecución de la Simulación SimulationRunner (subprocess OASIS/CAMEL-AI)

¿Qué hace? Lanza la simulación en un subprocess Python independiente. Los agentes interactúan en plataformas simuladas de Twitter y/o Reddit por N rondas. Cada acción (tweet, like, comment, follow) queda registrada. Actualizaciones en tiempo real vía polling.

POST /api/simulation/start → Inicia subprocess de simulación GET /api/simulation/run-state/{id} → Estado en tiempo real POST /api/simulation/stop → Detiene la simulación
camel-oasis 0.2.5 camel-ai 0.2.78 LLM (agent decisions) Twitter + Reddit

Outputs: actions.jsonl (log completo de acciones), run_state.json (estado de ejecución)

MinkOracle – Documentación Técnica v0.1 github.com/tatanGod17/mirofish
4
Generación del Reporte ReportAgent – Patrón ReACT

¿Qué hace? El ReportAgent utiliza el patrón ReACT (Razonamiento → Acción → Observación) para generar un reporte multi-sección de análisis de la simulación. Llama herramientas de Zep para recuperar contexto relevante, analiza los logs de acciones y produce insights profundos con hasta 2 rondas de reflexión por sección.

POST /api/report/generate → Genera reporte asíncrono con ReportAgent GET /api/report/{id} → Recupera el reporte generado (texto + PDF)
ReACT Pattern LLM (temp=0.5) InsightForge + PanoramaSearch Max 5 tool calls

Outputs: report.md, report.pdf (HTML corporativo), agent_log.jsonl (trazabilidad completa del razonamiento)

5
Interacción Profunda ReportAgent – Modo Chat

¿Qué hace? Permite al usuario hacer preguntas de seguimiento al ReportAgent. El agente mantiene contexto del reporte generado y puede recuperar información adicional del Knowledge Graph de Zep para responder preguntas específicas sobre la simulación.

POST /api/report/{id}/chat → Envía mensaje al ReportAgent
Chat contextual Zep hybrid search LLM conversational Historial persistente

Outputs: Respuestas en tiempo real con razonamiento trazable. El historial de conversación se persiste con el reporte.

9. Comandos para Ejecutar el Proyecto

Requisitos Previos

  • Python 3.11+ — verificar con python3 --version
  • Node.js 18+ — verificar con node --version
  • uv — gestor de paquetes Python: pip install uv
  • Archivo backend/.env — con las credenciales configuradas (ver Sección 4)

Instalación (Primera vez)

Terminal — Instalación inicial
# 1. Clonar el repositorio git clone https://github.com/tatanGod17/mirofish.git cd mirofish # 2. Instalar dependencias del backend cd backend uv sync cd .. # 3. Instalar dependencias del frontend cd frontend npm install cd .. # 4. Crear archivo de credenciales cp backend/.env.example backend/.env # → Editar backend/.env con tus API keys

Ejecución del Proyecto

Terminal 1 — Backend Flask (puerto 5001)
cd backend uv run python run.py # → http://localhost:5001
Terminal 2 — Frontend Vue (puerto 3000)
cd frontend npm run dev # → http://localhost:3000
